# Book Halal — админка

Next.js 16 (App Router) + TypeScript. Управление книгами и RAG-индексом.

```bash
cp .env.example .env.local   # при необходимости поправить адреса
npm install
npm run dev                  # http://localhost:3000 → /admin
```

Нужны запущенные Go-бэк (`:8090`) и RAG-сервис (`:8000`). Войти можно только под пользователем с ролью `admin`.

## Архитектура — модульный монолит

```
src/
  app/            роутинг и сборка экранов из виджетов модулей (тонкий слой)
    api/          BFF: session (логин/логаут), backend/* и rag/* — прокси с токеном из cookie
  modules/
    auth/         вход, выход, сессия (server/ — серверная часть для BFF и proxy.ts)
    books/        каталог, загрузка PDF, карточка книги
    rag/          здоровье RAG, индекс, переиндексация, песочница вопросов
  shared/         UI-кирпичи, http-клиент, конфиг — ничего не знает про модули
  proxy.ts        редирект на /login без cookie
```

Правила (проверяются ESLint, `npm run lint`):

- Модуль импортируется только через публичный API: `@/modules/<name>` или `@/modules/<name>/server`.
- Внутри модуля — относительные импорты; выходить из модуля через `../../../` нельзя.
- Модули не импортируют `@/app`; `shared` не импортирует ни `modules`, ни `app`.
- Модули не зависят друг от друга напрямую: связи собираются в `app`.
  Например, `rag` получает страницы для переиндексации через проп `loadPages`, который экран берёт из `books`.

Изоляция на экране:

- Каждый блок экрана — `Widget`: своя загрузка данных, своё состояние и свой `ErrorBoundary`.
  Упавший виджет показывает ошибку и кнопку «Перезапустить», остальные продолжают работать.
- Стили — только CSS-модули рядом с компонентом. В `globals.css` лежат только токены (цвета, отступы) и reset.

## Авторизация

Токен Go-бэка хранится в httpOnly-cookie и в браузер не попадает. У RAG-сервиса своей авторизации нет,
поэтому `/api/rag/*` проверяет роль admin. В бэке пока нет `/me`, так что роль определяется
пробным запросом к admin-эндпоинту (см. `modules/auth/server/admin-check.ts`).
